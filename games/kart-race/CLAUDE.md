# ターボサーキット(kart-race)

スマホ横画面向けの 3D カートレース。Three.js を使う(このゲームだけの例外。ユーザー了承済み)。

## 技術ルール
- Three.js は importmap で `three@0.160.0` を unpkg から固定読み込み。npm・ビルドツールは使わない
- オンライン対戦だけ PeerJS(`peerjs@1.5.4`、unpkg)を使う(例外。ユーザー了承済み)。オンラインを選んだときだけ net.js が動的に読み込む
- 外部の3Dモデル・画像・音声は使わない。形は Box/Cylinder などの組み合わせ、テクスチャは Canvas で描く、効果音は Web Audio API
- 物理エンジンなし。速度・摩擦・向きの自作挙動。dt は `CONFIG.maxDelta` で上限
- 調整用の数値は `js/config.js` の `CONFIG` にまとめる。コメントは日本語(ユーザーは初心者なので丁寧に)
- 軽さ優先: setPixelRatio は最大2、影はシャドウマップを使わず足元の半透明の円、木は InstancedMesh、マテリアルは Lambert
- 任天堂などのキャラ・名前・コース・アイテムデザイン・音楽は使わない(オリジナル)

## ファイル
- `index.html` / `style.css`: 画面・操作ボタン・タイトル・縦向き案内
- `js/config.js`: CONFIG(カート性能・コース制御点・カメラ・傾き・描画)
- `js/track.js`: スプライン(CatmullRom)からコースを生成。`query(pos, hint)` で最寄りの点番号と左右のずれ(offset)を返す。芝生判定・壁判定に使う
- `js/kart.js`: カートの見た目と挙動。前方 = (sin h, cos h)、右 = (-cos h, sin h)。右ハンドルで heading が減る
- `js/input.js`: キーボード / タッチ(elementFromPoint で全指を再判定)/ 傾き(横向き時は beta、画面の向きで符号反転)
- `js/main.js`: レンダラー・カメラ追従・ループ・タイトル

## 注意
- カメラから見て画面右 = ワールドの -x。ミニマップを作るときは x を反転して描かないと左右が逆になる

## 進め方(ユーザー指定の順番。各段階でユーザーのOKを待つ)
1. [x] 最小版: コースを1台で走れる(加速・ハンドル・カメラ追従・スマホボタン・傾け操作・キーボード)
2. [x] ドリフト(曲がりながら押し続けると火花の色が変わり、離すとミニターボ)
   - `js/effects.js`: 火花(Points 1つ)とターボの炎。`kart.addBoost(秒)` はアイテムのダッシュでも使う
   - `?debug` を付けると `window.kart` が見える(テスト用)。`?touch` で PC でもスマホ扱い(ボタン表示+自動アクセル)
   - スマホはアクセル自動(ユーザー要望: DRIFT が押しづらかったため)。ボタン操作 = 左 ◀▶ / 右 BRAKE+大DRIFT、傾け操作 = 左 大DRIFT / 右 BRAKE。PC は画面ボタンなし
   - ITEM ボタンを足すときは DRIFT の上あたり(右手側)に置く
3. [x] 周回・チェックポイント(3周、逆走・ショートカット防止、ラップタイム)
   - `js/race.js`: LapCounter(カートごと)。10区間を順番に通過+ライン通過で1周。直前に数えた周はラインを後ろに戻ると取り消す。`progress()` が順位用の値
   - 簡易ゴール画面とベストタイム保存(localStorage `kart-race-best-total` / `kart-race-best-lap`、秒)。catalog.js の best() は合計タイムを表示
   - 順位付きのリザルト・カウントダウンは手順6で
4. [x] CPU 3台(コース上の目標点を追う、強さ3段階をタイトルで選択)
   - `js/ai.js`: KartAI がカートへの入力を作る(物理はプレイヤーと共通)。ふつう以上はドリフトも使う。端に寄ると中央へ補正。動けなくなったら 2.5 秒でコース中央に復帰
   - main.js の `racers`(プレイヤー + CPU)。プレイヤーはスロット3(最後尾)。カート同士は `collideKarts` で押し合う。差が開くと CPU の速さを catchUp で少し調整
   - `?debug` で `simulate(秒, each)` による早送りができる。調整後の目安(3周): かんたん 87〜93秒 / ふつう 74〜79秒 / むずかしい 70〜73秒、芝生に出る時間はほぼ0
   - lookAheadPerSpeed を大きくすると、カーブの内側を突っ切って芝生に出る(調整済み)
   - スマホ専用の操作の手助け(ユーザー要望: キーボードなら「ふつう」がちょうどいいが、スマホだと勝てない)。CONFIG.assist
     - ◀▶ のじわっと入力(input.js)。ハンドルアシスト(ai.js `assistSteer` + main.js `playerInput`): 触っていないときはコースに沿って自動で切り、端では強める。外へ切っていると少し戻す
     - 目安: ◀▶ を一切押さないと「ふつう」で4位(82秒、CPU は78〜81秒)。少し操作すれば勝てるバランス。CPU の強さはスマホと PC で共通のまま
4.5 [x] オンライン対戦(ユーザー要望で手順5の前に割り込み)
   - `js/net.js`: PeerJS の部屋(4けたの番号、ID は `turbo-circuit-kart-room-` + 番号)。ホスト中心の星形。idx 0〜3(ホスト0)= カートの番号(entry)。ping 1秒・8秒無応答で切断扱い。レース中(locked)は参加不可
   - main.js の `racers` は4台固定(entry 0 赤 / 1〜3 青緑黄)。kind = 'me' / 'cpu' / 'remote'。人はグリッド後方から。CPU はホストだけが運転し、参加者側では remote
   - 各端末が自分のカートの物理と周回を計算し、状態(13個の数字の配列)を 20回/秒 送る。参加者→ホスト→全員。`raceNo` で前のレースのデータを捨てる
   - remote カートは `kart.updateRemote`(速度で先読み+ずれを smoothing で補正)。`collideKarts` は remote を動かさず自分側だけ押す
   - 順位: ゴール済みはゴールタイム順、それ以外は progress(remote は届いた値)。オンラインだけ 3・2・1 のカウントダウンとゴール画面の全員の順位表
   - ホストのゴール画面ボタン = もう一度 / ロビーへ。参加者 = 退出(次のレースはホストが始める)
   - 制限: TURN サーバーなしなので、学校・会社・一部の携帯回線ではつながらないことがある。ホストのタブが裏に回ると止まる
   - アイテムを足すときは、取った・置いた・当たったをイベントとして送る必要がある
5. [ ] アイテム(アイテムボックス → ダッシュ / 障害物設置でスピン)(作成済み・ユーザーの確認待ち)
   - `js/items.js`: Items(ボックスとパイロンの管理だけ)。ボックスは CONFIG.items.boxRows の3か所に4個ずつ、取ると4秒で復活。パイロンは id つき(`entry-raceNo-通し番号`)、消えた id は `gone` に覚えて置き直さない
   - アイテムは 'dash'(addBoost)と 'pylon'(真後ろに置く。当たると kart.spinOut で1秒操作不能+減速+車体が回る)。後ろの順位ほどダッシュが出やすい。取ってから rollTime 秒はルーレット表示で使えない
   - main.js: giveItem / useItem(ボタンを押した瞬間だけ)。ボックス・パイロンの当たりは、その端末で動かしているカートだけ調べて sendEvent で知らせる('ev' メッセージ、e = box / pylon / hit。ホストが全員に転送、2回届いても大丈夫)
   - スピンは状態のフラグ 8 で送り、remote は見た目だけ回す
   - CPU(ai.js): 持ったら 0.5〜3 秒待って使う。ダッシュはまっすぐな所で
   - 操作: スマホは DRIFT の上に ITEM(傾け操作では BRAKE の上)、PC は Space。持っているアイテムは順位の下に表示
   - アイテムを入れたので、手順4のタイムの目安(simulate)はずれている可能性がある
6. [ ] UI と効果音(カウントダウン・順位・ミニマップ・リザルト・ベストタイムを localStorage・share.js・catalog.js の best())
